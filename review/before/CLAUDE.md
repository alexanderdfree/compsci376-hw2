# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Homework 2 for Duke's *Computational Approaches to Human Language* (COMPSCI 376 / LINGUIST 399, Fall 2026); the parent repo holds one subfolder per assignment. The assignment materials (lecture slides, instructor code examples) live on Canvas course 84672 under Modules, not in this repo. Instructor examples use the Brown corpus; this folder re-runs them on the `inaugural` corpus and adds a tweaked sentence generator. `ANSWERS.md` is the write-up that gets submitted.

## Environment and commands

Python lives in the `compsci376` conda env (miniforge), shared by the whole course repo (`../requirements.txt`). NLTK data is in `~/nltk_data`; `corpus_config.py` downloads whatever corpus it needs on import, so a fresh machine only needs the package install. Run scripts from inside this folder so the sibling `corpus_config` import resolves.

```bash
conda activate compsci376                # or use ~/miniforge3/envs/compsci376/bin/python directly
pip install -r ../requirements.txt

./run_all.sh                             # regenerate every file in output/ (seed 376, ~20 s)
python basic_lm.py 376                   # one script; the optional arg is the random seed
python improved_lm.py --help             # tweaked generator; all knobs are flags
python improved_lm.py --start boundary --context 1 --min-len 6 --max-len 30 --novel -n 10 --seed 376
python improved_lm.py --corpus state_union --seed 1   # any NLTK plaintext corpus with .sents()
```

There is no test suite or linter; correctness is judged by reading `output/` and the assignment questions.

## Layout and how the pieces fit

- `originals/` holds the instructor's five Brown-corpus scripts byte-for-byte (filenames contain spaces). Never edit them; they are the reference for what the baseline does. Each has a snake_case adaptation in this folder:

  | original (Brown)                                            | adapted (uses `corpus_config`) |
  |-------------------------------------------------------------|--------------------------------|
  | `BigramFrequencies.py`                                      | `bigram_frequencies.py`        |
  | `UnigramBigramTrigramFreq.py`                               | `ngram_freq.py`                |
  | `UnigramBigramTrigramNoPuncFreq.py`                         | `ngram_freq_nopunct.py`        |
  | `Basic LM with Sentence Generation.py`                      | `basic_lm.py`                  |
  | `Basic LM with Sentence Generation with Random Starting Bigram.py` | `basic_lm_random_start.py` |

- `corpus_config.py` is the single switch for which corpus every adapted script uses (`CORPUS_NAME`); scripts import `corpus` from it rather than `nltk.corpus.<name>` directly.
- All generators share one model shape: `model[(w1, w2)][w3]` = count, built from `trigrams(sent, pad_left=True, pad_right=True)`, so `None` marks sentence boundaries and generation stops when `None` is sampled. Despite the file name, the "starting bigram" is the two-word *context* of a trigram LM, not a bigram model. `improved_lm.py` generalises this to `--context K` and adds start strategy, punctuation stripping, length filtering, and a verbatim-copy check.
- `output/` is fully generated by `run_all.sh`; `ANSWERS.md` quotes from it, so rerun the script before changing the answers. `output/comparison.txt` is the 500-sentence statistics table behind question 4.

## Gotchas

- The `inaugural` corpus's post-2009 files are read by NLTK as Latin-1, producing junk tokens (`\x80\x94`, `¡`, a stray `â` glued to words). `improved_lm.py` strips non-ASCII bytes; the faithful adaptations deliberately do not.
- `string.punctuation` (used by the NoPunc original) only matches single characters, so `--`, `."`, `...` survive its filter. `ngram_freq_nopunct.py` reports those survivors.
- The original `Basic LM` prints `dict(model["part","of","the"])`, a 3-tuple key on a 2-tuple-keyed dict, so it always prints `{}`; `basic_lm.py` prints the intended `("of", "the")` distribution instead.
- The original generators loop forever if a starting context is absent from the model; keep starting words that occur in the chosen corpus.
