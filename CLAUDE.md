# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Homework 2 for Duke's *Computational Approaches to Human Language* (COMPSCI 376 / LINGUIST 399, Fall 2026), packaged as a standalone repository. The assignment materials (lecture slides, instructor code examples) live on Canvas course 84672 under Modules. Local instructor examples are preserved in `originals/`. They use the Brown corpus; this repository re-runs them on the `inaugural` corpus and adds a tweaked sentence generator. `ANSWERS.md` is the write-up that gets submitted.

## Environment and commands

On the original machine, Python lives in the `compsci376` conda env (miniforge). A clone can use a virtual environment and the repository's `requirements.txt`; see `README.md`. NLTK data is normally in `~/nltk_data`; `corpus_config.py` ensures both the selected corpus and `punkt_tab` sentence-tokenizer data are downloaded. A fresh machine needs the Python package and these data resources; the first script run can download the resources automatically. Run scripts from inside this folder so the sibling `corpus_config` import resolves.

```bash
conda activate compsci376                # or use ~/miniforge3/envs/compsci376/bin/python directly
pip install -r requirements.txt
python -m nltk.downloader inaugural punkt_tab  # explicit setup; also done by corpus_config

./run_all.sh                             # regenerate every file in output/ (seed 376, ~20 s)
python basic_lm.py 376                   # one script; the optional arg is the random seed
python improved_lm.py --help             # tweaked generator; all knobs are flags
python improved_lm.py --start boundary --context 1 --min-len 6 --max-len 30 --novel -n 10 --seed 376
python improved_lm.py --corpus state_union --seed 1   # any NLTK plaintext corpus with .sents()
```

Run `python review/verify.py` to check the tables, samples, and correction invariants against the preserved snapshot. It writes to the ignored `.review-work/` directory. Historical audit records live under `review/`; use the root assignment files as the current versions.

## Layout and how the pieces fit

- `originals/` holds the instructor's five Brown-corpus scripts byte-for-byte (filenames contain spaces). Never edit them; they are the reference for what the baseline does. Each has a snake_case adaptation in this folder:

  | original (Brown)                                            | adapted (uses `corpus_config`) |
  |-------------------------------------------------------------|--------------------------------|
  | `BigramFrequencies.py`                                      | `bigram_frequencies.py`        |
  | `UnigramBigramTrigramFreq.py`                               | `ngram_freq.py`                |
  | `UnigramBigramTrigramNoPuncFreq.py`                         | `ngram_freq_nopunct.py`        |
  | `Basic LM with Sentence Generation.py`                      | `basic_lm.py`                  |
  | `Basic LM with Sentence Generation with Random Starting Bigram.py` | `basic_lm_random_start.py` |

- `corpus_config.py` is the single switch for which corpus every adapted script uses (`CORPUS_NAME`); scripts import `corpus` from it rather than `nltk.corpus.<name>` directly.
- The baseline generators count `model[(w1, w2)][w3]` with `trigrams(sent, pad_left=True, pad_right=True)` and then normalize the counts into probabilities. `None` marks sentence boundaries; the baselines stop after two trailing `None` values, while the rewrite stops at the first sampled `None`. Despite the file name, the "starting bigram" is the two-token *context* of a trigram LM, not a bigram model. `improved_lm.py` generalises this to `--context K` and adds start strategy, punctuation stripping, length filtering, and an exact cleaned-corpus sentence-copy check.
- `output/` is fully generated by `run_all.sh`; `ANSWERS.md` quotes from it, so rerun the script before changing the answers. `output/comparison.txt` is the 500-sentence statistics table behind question 4.
- The comparison table contains configurations of the rewritten generator, including its uniform-start configuration. It is not a measurement of the untouched baseline. Lengths count tokens, including punctuation; percentages use one decimal place and include raw counts.
- The checked environment is Python 3.12.14 / NLTK 3.10.3, with 60 inaugural addresses from 1789 through 2025. Reproducing exact outputs also requires the same corpus and tokenizer data; a random seed alone does not pin those resources.

## Gotchas

- The `inaugural` corpus's post-2009 files are read by NLTK as Latin-1, producing junk tokens (`\x80\x94`, a stray `â` glued to words). Older text also contains encoding artifacts such as `¡`. `improved_lm.py` strips non-ASCII characters; the faithful adaptations deliberately do not.
- `word in string.punctuation` (used by the NoPunc original) tests whether the token is a substring of that string. Tokens such as `--`, `."`, and `...` survive its filter. `ngram_freq_nopunct.py` reports those survivors.
- Periods usually precede the sentence-end padding, but abbreviations such as `Mr . Jefferson` do not. Boundary starts sample observed openings, which can include quotes or parentheses; they do not guarantee a punctuation-free start. Stripping punctuation retains the `None` stopping marker.
- The original `Basic LM` prints `dict(model["part","of","the"])`, a 3-tuple key on a 2-tuple-keyed dict, so it always prints `{}`; `basic_lm.py` prints the intended `("of", "the")` distribution instead.
- The original generators loop forever if a starting context is absent from the model; keep starting words that occur in the chosen corpus.
